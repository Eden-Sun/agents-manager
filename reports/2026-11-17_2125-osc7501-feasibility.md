# #2125 claude OSC 7501（Program Status Protocol）可行性 Phase A

調查時間：2026-11-17 16:00–16:25 (+8)。claude 2.1.326、herdr 0.9.5、Linux（ubuntu）。只做調查與 fixture，未改任何判讀邏輯。

## 結論

1. **序列格式已取得**，狀態有 `idle / working / done / blocked / clear` 五種，另有 `?` 探測。
2. **claude 不會主動送狀態，要終端機先回應探測才啟用**（見下）。
3. **herdr 0.9.5 不回應 `OSC 7501;?`（只回 DA1 `ESC[?62;22c`），也不把 OSC 帶進 `pane read`**（visible／recent／detection、text／ansi 全部沒有 7501）。所以現況下在 herdr 裡的 claude 根本不會送狀態，AG Man 拿不到。
4. 要採用，必須先有人（herdr 或 AG Man 自己的 PTY 層）回應探測並保存 OSC；AG Man 端只改 lifecycle 的判讀不夠。

## 握手

claude 啟動時送：`ESC ] 7501 ; ? BEL` 緊接 `ESC [ c`（DA1，當探測哨兵）。終端機必須回一個 `OSC 7501` 且 data 以 `?` 開頭的序列（claude 的 matcher：`osc && code===7501 && data.startsWith("?")`），例如 `ESC ] 7501 ; ? BEL`（本次實測回這個即可啟用）。只回 DA1 → claude 記 `probe: no reply to OSC 7501 ; ?`，之後不送狀態。離開時送 `state=clear`。回應格式的正式規格未公開，`?` 之後是否有欄位（版本／能力）未知，實測只要以 `?` 開頭就接受。

## 狀態序列（`ESC ] 7501 ; <k=v>[:<k=v>…] BEL`，分隔符 `:`）

欄位：`state`（必）、`app=claude-code`、`id`、`kind`（僅 blocked）、`progress`（0–100，僅 working／blocked）、`title`、`msg`（**base64**）。

| 場景 | 序列（實測） |
|---|---|
| trust 提示開著 | `state=blocked:app=claude-code:kind=permission:msg=dHJ1c3QgdGhpcyBmb2xkZXI=`（msg＝`trust this folder`） |
| trust 選 No 離開／正常離開 | `state=clear`（離開時送，沒有 `app`） |
| 通過 trust、輸入框就緒 | `state=idle:app=claude-code` |
| 送出 prompt 開始回合 | `state=working:app=claude-code` |
| 工具執行中 | `state=working:app=claude-code:msg=<base64>`（例：`Creating empty file zz.txt`） |
| 回合結束 | `state=done:app=claude-code` |

2.1.326 changelog 另提：背景指令／monitor／MCP 任務會列出，等待它們時顯示 working 而非 done；compaction 後與 `claude agents`／`attach`／`--resume` 的背景 session 也會送。這幾個情境本次**未實測**（沒有受管 bot 可用，且 attach 要 daemon）。工具權限提示的 `blocked`（kind 是否為 permission 以外值）也只實測了 trust 這一種；本次的 `touch` 在 bypass 外也沒觸發提示。

## fixture（`crates/am-lifecycle/src/lifecycle/fixtures/`，原始位元組，已把使用者名與暫存目錄名替換成 `agent`／`XXXXXXXXXX`）

- `claude-2.1.326-osc7501-probe-noreply.bin`：終端不回應，只有探測（`?`）無狀態。
- `claude-2.1.326-osc7501-trust-blocked.bin`：回應探測後，trust 提示 → `blocked`。
- `claude-2.1.326-osc7501-trust-decline-clear.bin`：trust 選 No 離開 → `clear`。
- `claude-2.1.326-osc7501-turn-idle-working-done.bin`：通過 trust → `idle` → `reply OK` → `working` → `done`。
- `claude-2.1.326-osc7501-tool-working-msg.bin`：工具執行帶 `msg` 的 working。

錄法：Python `pty.fork` 拋棄式 `mktemp -d`，視窗 120x40，`TERM=xterm-256color`，收到 `ESC]7501;?` 就回 `ESC]7501;?BEL`，收到 DA1 就回 `ESC[?62;22c`。錄完 kill 自己的 PID。trust 選 Yes 會在 claude 設定檔留下該暫存目錄的信任紀錄（已是拋棄式路徑）。

## herdr 穿透實測

- 在拋棄式 herdr pane 跑 claude（`--dangerously-skip-permissions`），送 `reply OK` 後反覆 `herdr pane read --source visible|recent|detection --format text|ansi`：七種組合的輸出都**沒有** `7501`（也沒有任何 OSC，herdr 的模擬器會吃掉）。
- 在另一個拋棄式 pane 用 raw-mode 腳本送 `ESC]7501;?BEL ESC[c`：stdin 只收到 `ESC[?62;22c`，沒有 7501 回應。→ herdr 不支援此協定，claude 在 herdr 內會判定「終端不支援」而完全不送狀態。
- `pane_text.rs` 的 `clean_for_claude` 是**送進 claude 的文字**的清洗（剝 OSC／CSI），不在讀畫面路徑上；AG Man 讀畫面是 `am-base/src/herdr.rs` 的 `pane_read`／`pane_read_ansi`，那條路在 herdr 端就已沒有 OSC，所以「在 pane_text.rs 剝除之前拿得到」＝**拿不到**。

## 若要採用（只是建議，需另開票）

1. 由能看到原始位元組的一層處理：herdr 本身（回應 `OSC 7501;?`，並把最新一筆 state 暴露在 `pane get`／`agent_status` 或 pane read 的 metadata），或 AG Man 若自管 PTY 就在那層攔。AG Man 只能透過 herdr API 讀畫面，單靠 AG Man 無解。
2. herdr 回應探測後，所有受管 claude 才會送狀態；對應到 AG Man：`blocked`→waiting on user、`working`→busy、`idle／done`→ready，`clear`→session 結束。`msg` 要 base64 解碼，`kind` 與 `progress` 可選用。
3. AG Man 側（lifecycle／screen.rs）：以結構化狀態為主，缺席時（舊 claude、非 herdr）回退畫面解析；解析時 `state` 未知值要忽略，不可當錯誤。
4. 風險：協定規格未公開、changelog 逐版仍在調整（2.1.326 內就改了三項）；採用前需綁版本實測，並保留畫面解析作為對照與回退。
5. 先別動：在 herdr 支援前，#2125 的驗收（「working／waiting／done 與實際一致」）無法在現行部署達成。
