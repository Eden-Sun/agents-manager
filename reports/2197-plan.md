# #2197 Phase A：daemon lib test 熱區與拆分計畫

量測基底 `ab49d4f131b207b4278cf4eb9094a2c3577bfe35`，已包含 #1862 的 am-lifecycle 撤掛載。這一階段只量測與規劃，樣本的暫時空白改動已還原。歷史數值及 r7 對照在 [check-speed.md](check-speed.md)；本輪只量 Ubuntu，r7 留給每刀的前後驗收。

## 增量時間

Ubuntu（16 邏輯核），受管 Cargo shim、同一 `ubuntu@127.0.0.1` 熱池 `shared`，固定執行 `cargo test -p agents-managerd --no-run --timings`。每次先過 `scripts/wait-load.sh --max 4 --min-free-mem 30`，等待不計入秒數。三輪正式樣本進場一分鐘負載 1.72、1.78、2.00。熱池共用，沒有獨占資格，沒有把結果當成精確到一秒的收益證據。

| 情境 | 命令牆鐘（秒） | daemon lib test（秒） | 一般 daemon lib（秒） |
| --- | ---: | ---: | ---: |
| 預熱（排除） | 91.62 | 73.28 | 26.74 |
| `webpush.rs` 1 | 64.49 | 58.90 | 17.71 |
| `webpush.rs` 2 | 67.79 | 62.96 | 18.51 |
| `webpush.rs` 3 | 65.40 | 59.81 | 17.84 |

| `api_bot/runtime.rs`（探索，1 筆） | 75.86 | 69.89 | 24.89 |

每筆正式樣本只改一個檔案尾端的空白，保持程式語意。探索樣本循序累加，一次只改一個檔案，取完一起還原。探索時進場負載 2.79／3.41，兩筆只表示這兩個編輯同樣會觸發整顆 daemon lib test，不能將差值當成模組自身用時。Cargo unit 時間有重疊。三筆主樣本中 daemon lib test 持續到建置尾端，一般 lib 約 18 秒，後續 bin 與 API parity 完成得更早。

## Rust 編譯階段與模組熱點

另在同一台 Ubuntu 用現有穩定版 rustc 1.98.1、受管 Cargo 與隔離的診斷 target 編 daemon lib test。只為這顆 Rust crate 啟用診斷旗標，先填滿 target，再改同一檔案尾端一行。這不是 `shared` 基準的第四筆。兩種建置的 daemon lib test 普通及 ignored 清單一致。指令如下，其中 DATA 為獨立目錄。

```sh
mkdir -p "$DATA/profile" "$DATA/mono"
RUSTC_BOOTSTRAP=agents_managerd cargo rustc --locked -p agents-managerd \
  --profile test --lib --target-dir "$DATA/diagnostic-target" -- \
  -Ztime-passes -Zself-profile="$DATA/profile" \
  -Zdump-mono-stats="$DATA/mono" -Zdump-mono-stats-format=json
```

| rustc 階段 | 隔離 target 冷編（秒） | 同診斷 target 增量（秒） |
| --- | ---: | ---: |
| Macro 展開 | 11.70 | 13.29 |
| 名稱解析 | 2.69 | 3.03 |
| 型別檢查（含 coherence） | 142.60 | 4.51 |
| MIR borrow checking | 108.40 | 1.68 |
| Monomorphization graph walk | 148.98 | 7.06 |
| Codegen unit 分割及符號檢查 | 16.54 | 7.52 |
| 生 LLVM IR | 89.37 | 0.00 |
| LLVM passes | 81.71 | 0.03 |
| 增量依賴圖及查詢快取序列化 | 7.73 | 13.82 |
| Linker | 3.79 | 3.93 |
| **rustc total** | **559.72** | **73.97** |
| Cargo 命令牆鐘 | 645.04 | 74.65 |

Rustc 的階段有巢狀和並行，不能直接加總成總時間。一次隔離增量診斷看到約 13 秒展開、約 15 秒遍歷和分割 monomorphization、約 14 秒寫增量快取，且幾乎重用了全部 LLVM codegen。改語意時可能重做更多 LLVM。此處 linker 約 4 秒，因此單靠換 linker 或以產物大小推算 link 省時，無法解釋約 60 秒的熱池 lib test。冷編仍有大量型別、borrow checking 及 LLVM 工作，不能當作一行編輯的成本。

模組沒有可直接相加的編譯計時。用 rustc `-Zdump-mono-stats` 的 `total_estimate` 按定義路徑分組，和上面的符號大小及測試清單交叉核對。數值是 monomorphization 估量，單位為千個 compiler estimate，不能當秒數或實際 IR 行數。

| 群組 | Monomorphization 估量（千） | 可定位的代表 |
| --- | ---: | --- |
| `lifecycle_tests` | 568.4 | `poller` 202 條、`hookrecv` 180 條、`start` 120 條 |
| `runners` 其他 | 377.2 | `pending_question::remote_tests::rig_with`、`relay_requests::reconcile` |
| `api` | 354.1 | `prompt_bot`、`patch_bot`、`state_json`、`router` 的定義／future |
| `runners::am_base_tests` | 329.2 | herdr shim 115 條、Cargo shim 70 條、quota 69 條 |
| `api_bot` | 317.1 | `run_with_codec` 的 future 有 8 個具體化，`spawn_tracked` 有 32 個；`runtime` 122 條，`pricing` 18、`sse` 11、`protocol` 7 |
| `supervisor_tests` | 104.8 | `controller` 91 條、`idle_sleep` 51 條、`maintenance` 42 條 |
| `share_tests` | 51.0 | 共 103 條 |
| `api_bot` route／ledger 轉接 | 4.2 | 共 9 條 |
| 其他或無法歸屬的依賴與泛型 | 6,260.1 | 含 std、Tokio、SQLx、Axum 等共享具體化 |

`lifecycle_tests` 在可歸屬的測試機器碼與 monomorphization 都最大；`runners::am_base_tests` 則有最多可直接往現有 crate 查證的葉模組。API 與 API bot 的估量和 am-base 掛載群相近，但含較多共用的非測試路徑。宜先試刪 daemon 測試編譯單元中的葉測試和夾具，保留具體組裝。生產碼變成相依 crate 後仍會連進 daemon；若泛型在 daemon 端具體化，移動原始檔也未必移走編譯工作。

## 每刀的時間預算

這是排優先順序的估算，尚無實作後的實測。用診斷中約 51 秒可列出的展開、解析、型別、borrow checking、mono walk／分割與快取階段，和 62.61 MB 可歸名的 daemon 機器碼做粗略比例。每移出 1 MB 可歸名工作，比例上約 0.8 秒，實際會受共享泛型、跨 crate 重連結與測試夾具影響。表中的 MB 是相對現有符號的預計移出量，逐案盤點後再縮。秒數是 **daemon lib test 單元**的預估，無法相加當牆鐘收益。

| 刀 | 初始可移出估量（MB） | 預期省時（秒） |
| --- | ---: | ---: |
| B1 am-base 葉測試 | 2–4 | 1–3 |
| B2 lifecycle port 夾具及測試 | 3–7 | 1–5 |
| B3 supervisor 既有夾具可接的部分 | 0.5–1.5 | 0–1 |
| B4 API 純型別及讀投影 | 1–3 | 0–2 |
| B5 API bot 協定／定價純核心 | 0.8–2.5 | 0–2 |
| B6 daemon integration binary 試點 | 2–5 | 0–4，整體牆鐘可能不降或回升 |

原始 timing HTML、--list、階段日誌、`mono_items.json` 與 raw self-profile 保存於 Ubuntu 的 `/tmp/kx2197.BQM1uL/`。Phase A 未搬測試、未翻轉 crate、未執行 daemon 全量測試。下一刀以實際前後量測決定是否擴大。

## 拆分順序與驗收

每刀沿用 #1862 的順序。先逐條搬測試和窄夾具，再接可同時支援舊掛載與新 crate 的測試 gate，最後才翻轉進入點及移除重複編譯的掛載。既有 crate 可直接收測試時，翻轉只撤 daemon 的測試掛載。必須留在 daemon 的 HTTP、端到端與真實組裝測試繼續驗原有行為。

| 刀 | 邊界與先驗證的子集 | 順序及相依風險 |
| --- | --- | --- |
| B1 | `runners::am_base_tests` → 既有 `am-base`。先挑 herdr shim、Cargo shim、純模型／版本解析、同類假主機夾具，按實際依賴判斷。 | 先做 2–3 個葉模組。中低風險。共用的 migration／schema-drift 及 daemon composition 測試暫留，避免拿簡化 DB 對照替代完整遷移。掛載檔數是查核範圍。 |
| B2 | `lifecycle_tests` 的 leaf/port fixture 可回 `am-lifecycle`。先從 `poller`、`hookrecv`、`start` 各自列純 DB／fake port 子集。 | B1 的葉模組可平行盤點。中高風險。前三群分別有 202／180／120 條，很多仍使用 `testing::Env` 或 daemon port。保留 runner 所有權、hook 次序、測試 fence、出處及重試斷言。 |
| B3 | `supervisor_tests` → `am-supervisor`，以既有 `TestSupervisorEnv` 能承接的 idle、controller、responder 葉案例為限。 | 可與 B1/B2 葉模組平行盤點，檔案及夾具不交叉才平行實作。全 App 的 outbox、maintenance lease、ops 組裝保留。效益預估低，搭既有模組拆分一起做。 |
| B4 | API 先抽純 request/view 型別、解析與讀模型到窄 `am-api-view`。只有編譯後能消掉具體 App 實作或測試負擔再擴到 handler。 | 先逐路由列出 principal、auth、狀態和 DB 要求。中高風險。保留 daemon `api::router` 的唯一組裝、認證／scope layers、動態 route 的事件與交易順序。避免在 DAO 新建第二條寫路。 |
| B5 | `api_bot` 先抽協定、定價、quote 及同級可離線驗的純 runner 部件到 `am-api-bot-core`。 | 與 B4 純轉換可平行盤點。高風險階段留給第二刀：runtime、native start/prompt、receipt、retention、sweeper 直接依賴 App 的鎖、DB、sandbox、啟動 gate，原樣保留。確認一條受管 fake-provider 路徑後再決定是否移 adapter/tool。 |
| B6 | 仍需要 `Arc<App>` 的測試，挑一群搬到一個獨立的 daemon integration test binary，用現有裝配和 gate 下的窄 adapter。 | B2 後再試。一次一個 binary，先量是否減少整次命令牆鐘。新 binary 仍會重連結 daemon lib，可能抵銷 lib test 的收益。不要按檔案打散成大量 Rust test targets。 |

B1、B2、B3 的規劃和單一葉模組準備可由 lead 分派。串行合入有共同 `mod.rs`、fixture 或 Cargo feature 的刀。B4/B5 在純邊界可平行，API-bot 路由、App port、啟動／關閉編排串行。其餘 `runners` 先依測試保有者分回既有 crate，`remote_cargo` 單獨拆保持低優先，先取得超過雜訊的證據。

每刀用同一熱池與固定的 rustc／profile／jobs。Ubuntu 和 r7 各做一組，暖編後以 `webpush.rs`、`api.rs` 及 `api_bot/runtime.rs` 各自改一行，前後至少各 3 次，列所有樣本與中位數。兩個成功條件分開：daemon lib test unit 變小，以及 `cargo test -p agents-managerd --no-run` 牆鐘有可重現改善。低於本輪約 3 秒的牆鐘波動先視為未定，交錯前／後順序再驗。被抽走的 feature 若只改那個 crate，也量該 crate 的 test-only 快速路徑。

每刀逐 binary 比對普通與 ignored 清單，列出從 daemon 移到哪個 crate 的逐名對帳。保留原斷言，`scripts/check.sh changed`、掛載守門、`api_doc_parity`、`bot_scope_matrix` 與 1 MiB stack 守門綠才翻轉。若碰 Mac 敏感工具／runner，補 `macos-local`。每刀一個可快轉提交，報告實測秒數與殘留的共享依賴。
