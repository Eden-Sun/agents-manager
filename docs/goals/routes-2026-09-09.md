# 每個畫面都有自己的 URL（2026-09-09）

執行者：opus。遵守 `CLAUDE.md`（不要 stash、只 add 自己的檔、不要重啟 daemon）。新邏輯獨立成新檔，`store.ts` / `App.tsx` 的 hunk 要小。改完同步 `docs/FRONTEND.md`（新增「路由」一節）與 `docs/UI-DECISIONS.md`。

## 需求
現在整個 UI 只有 `/`，選了哪個 bot / project / team 都是 store 的狀態：重新整理回到首頁、上一頁沒作用、沒辦法把「這個 bot 的對話」的連結貼給別人或加到手機主畫面。每個畫面要有獨立的 path：

| 畫面 | path |
|---|---|
| 母 bot 對話 | `/bots/:botId` |
| 母 bot 終端分頁 | `/bots/:botId/terminal` |
| 子 bot（child）對話 | 同上 `/bots/:botId`（子 bot 也是 bot） |
| Project 群組聊天 | `/projects/:projectId` |
| Team | `/teams/:teamId` |
| 組隊（TeamLaunchPanel） | `/projects/:projectId/teams/new?issue=<n>` |
| 主機 shell | `/hosts/:host/shells/:paneId` |
| Bot 設定（浮窗／sheet） | `/bots/:botId/settings`（開著時 push，關掉時 back） |
| 首頁（沒選東西） | `/` |

- **不引進 router 套件**：`history.pushState` / `popstate` + 一個 `lib/routes.ts`（`parse(pathname) → Selection`、`build(selection) → pathname`、單元測試）就夠。
- **雙向同步**放在新檔 `store/routeSync.ts`：
  - store 的 `selectBot` / `selectProject` / `selectTeam` / `openHostShell` / `setRightTab` / `openSettings` / `closeSettings` / `teamLaunch` 改變 → `pushState`（同一個畫面內的切換用 `replaceState`，例如 chat↔terminal）。
  - `popstate` → 呼叫對應的 select。
  - 開頁時先 `parse(location.pathname)`，等 `refreshState` 拿到 state 後再套用（bot 不存在 → 回 `/` 並 notify）。
  - 手機抽屜開著時按上一頁：先關抽屜、不切畫面（用 `pushState` 一個 `#drawer` 或 state 物件記）。
- **token**：`?token=` 只在第一次載入用（transport 已快取），套用路由後從 URL 拿掉（`replaceState`），分享出去的連結不帶 token。
- daemon 的 SPA fallback（`daemon/src/assets.rs`）已經對任何路徑回 `index.html`，確認 `/bots/x/terminal` 這種多層路徑下 `assets/…` 相對路徑仍正確（`vite.config` 的 `base` 或 index.html 用絕對路徑）。Vite dev 也要能直接開 `http://127.0.0.1:5173/bots/<id>`。
- 側欄與所有「開啟 X」的按鈕維持現在的 onClick（走 store），**不要**改成 `<a href>`；但 bot 列、project 標題、team 節點可以加 `href` 讓「複製連結」／中鍵開新分頁可用（用 `<a>` 包 + `onClick` preventDefault）。
- 標題：`document.title` 跟著畫面變（`C1-fable · AG Man`、`#56 … · Team · AG Man`）。
