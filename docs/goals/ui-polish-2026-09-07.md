# Goal：agents-manager Web UI 打磨（自主迭代至 2026-09-07 06:00 台北時間）

## 目標
讓 http://127.0.0.1:5173/ 的實機畫面（真 daemon，不是 mock）在桌機 1440、1024 與手機 390 三種寬度、深色與淺色都「乾淨、可讀、沒有實作細節外漏」。每一輪：看畫面 → 挑最礙眼的一項修 → 驗證 → commit。到 06:00 或清單做完就停。

## 硬規則
- 只改 `web/` 底下的檔案。不要動 `daemon/`、不要 `cargo build`、不要重啟 daemon（其他 agent 正在用它）。5173 是 vite dev server，會自動熱更新。
- 每一輪結束都要過 `cd web && npx tsc --noEmit && npx oxlint src && npm run build`，然後 `git add web/ && git commit`（訊息用 `fix(web): …` 或 `feat(web): …`，繁體中文或英文皆可）並 `git push origin main`。**只 add `web/` 與 `docs/screenshots/`**，工作樹裡其他人的檔案不要碰、不要 stash。
- 截圖用 `OUT=docs/screenshots/goal node scripts/ui-goal-shots.mjs`（headless Chrome，會存 s1～s7 七張），看圖用 Read 工具。不要用 Playwright，不要開會搶焦點的瀏覽器視窗。
- 看到 `docs/UI-DECISIONS.md` 裡已經定案的決定不要翻案；新的取捨補寫進去。
- 不確定的視覺取捨，選「更少、更安靜」的那個。不要加新功能。
- 到 06:00（用 `date` 確認）就停：最後一輪 commit + push，然後在對話裡列出做了什麼、還剩什麼。

## 已觀察到的問題（依礙眼程度排序，從上面開始）
1. [x] **對話裡的「輸出中」即時氣泡把終端雜訊原樣印出來**：例如 `Pushed to main, ran 1 shell command`、`(ctrl+b to run in background)`、`Tip: Use /btw to ask…`、`✘ Auto-update failed · Run claude doctor`、一段 shell 指令原文。這是 `terminal_fallback` / `turn_progress` 的擷取文字直接進了 `LiveBubble`。應在前端過濾 CLI 的狀態列、Tip、鍵盤提示、更新提示等固定樣式行，只留 agent 真的在講的話；擷取太髒時退回只顯示活動摘要（`activity`）。相關：`web/src/components/ChatPanel.tsx` 的 `LiveBubble`、`web/src/store/store.ts` 的 `liveReplyOf`。
2. [x] **手機（390px）標題列擠爆**：bot 名字剩 `C1-F…`、pane 標籤剩 `W.. ▾`、額度框佔掉一半寬度，下方 context bar（帳號 / context / 花費 / 版本）被右邊裁掉。手機上額度框應縮成一顆小 chip、pane 標籤隱藏、context bar 可橫向捲動或只留最重要的兩項。
3. [x] **Team 面板上半部太重**：issue 佇列 + Task 清單把群組對話擠到剩三分之一高。佇列與 Task 預設收合成一列摘要（`佇列 6 · 已交付 3 · 待處理 2`、`Task 7 · 審查中 1 · 完成 6`），點開才展開；或把兩區改成可摺疊。
4. [x] **Team 標題列兩顆紅色破壞性按鈕（中止、刪除）緊鄰**：把「刪除」移到更遠的位置或放進「⋯」選單，中止保留。
5. [x] **時間軸事件文案技術味**：`note reply_ok：role=pm`、`回覆結尾必須包含一個 ```am-team fenced 區塊…` 這種系統對 agent 講的話出現在給人看的時間軸。前者改成「PM 已回覆」這種人話或直接隱藏；後者（協定提醒）折進「系統」摺疊區。
6. [x] **側欄 bot 列的活動摘要截太短**（`Claude 模型…`、`預設上方he…`），而且名字與摘要同一行搶空間。摘要另起一行、用 `--text-faint`，或 hover 才顯示完整。
7. [x] **模型徽章 `opus-高` / `grok-4.6-中` 用連字號拼接**，讀起來像模型名的一部分。改成 `opus · 高` 或把強度做成獨立小 chip。
8. [x] **終端分頁的提示文字「唯讀快照，第一階段不做 xterm.js 串流」是開發備忘**，改成給使用者看的「唯讀快照，每次按刷新更新」。
9. [x] **小字太多**：目前頁面有 89 個可見文字元素小於 11px。徽章、meta、chip 統一最小 11px；只有 mono 的細節數字允許 10.5px。
10. [x] **對比**：`.bot-state.agent-title` 在選取列上只有 4.49:1，補到 4.5 以上（改 `--text-faint` 在 `.selected` 的用色）。
11. [x] **1024px 寬**：標題列的額度框、`+4`、對話/終端分頁擠在一起但還可用；若第 2 項的手機規則做成 `≤1024` 也適用，就一起處理。

## 每一輪的固定流程
1. `date`；超過 06:00 就進入收尾。
2. 跑截圖腳本，Read 七張圖，對照上面清單挑一項（或你新發現、比清單更礙眼的一項）。
3. 改碼，`npm run build` 通過，再跑一次截圖確認真的變好、沒有別的畫面壞掉。
4. commit + push。把做完的項目在這份檔案裡打勾（`- [x]`），新發現的加到清單尾端。

## 本輪新增的取捨（`docs/UI-DECISIONS.md` 之外，避免動到別人的檔案）

- **即時氣泡的擷取文字一律先過濾**（第 1 項）：新增 `web/src/store/liveText.ts`，以「行」為單位刷掉
  CLI 的動作摘要（`Read 7 files, ran 2 shell commands`）、`Tip:`、鍵盤提示、`Auto-update failed`、
  被回顯的 shell 指令與框線；濾完什麼都不剩就回 `null`，讓氣泡退回顯示 `activity`。
  取捨：寧可誤刪一兩行擷取來的雜訊，也不要讓終端細節外漏；判定條件刻意保守（要求無句尾標點、
  含數字、非中文），所以 agent 真的在說的英文句子（`Pushed to main.`）不會被吃掉。
  `activity` 只剝掉尾巴的按鍵教學，狀態本身保留。
- **手機標題列只回答三件事**（第 2 項）：新增 `@media (width <= 640px)`。額度縮成一顆 chip——
  量表換成 `7d 59%` 的數字（UI-DECISIONS 說風險不能只剩顏色，所以留數字而不是只留顏色），
  完整數字仍在點開的 popover；模型徽章、repo 的 owner、`帳號` 欄讓位，標題列回到一行。
  順帶修掉 `@media (width <= 1080px)` 裡對 pane chip 無效的那條規則（`.main-status.pane-toggle`
  兩個 class，後面又定義了一次 `display: inline-flex`，特異性贏過 media query 裡的裸 `.main-status`），
  1024px 也跟著鬆開。
- **Team 的 issue 佇列與 Task 清單預設收合**（第 3 項）：兩段本來就有 disclosure，只是預設展開，
  把群組對話擠到剩三分之一。改成預設收起、只留摘要那一行；但「非看不可」的情況會自己打開——
  佇列有 `失敗`、Task 有「需要你」時。使用者手動按過之後就以他的選擇為準（`override ?? 預設`），
  不用 effect 去追狀態。
- **Team 標題列的「刪除」收進 `⋯`**（第 4 項）：新增 `HeadMoreMenu`（`Icons.tsx` 的 `MoreIcon`
  \+ `.head-menu*` 樣式）。中止／清理留在外面當唯一的常駐危險操作，紅色只出現在選單項目與
  接下來的確認框——這是 UI-DECISIONS 已定的「紅色不作為常態列表色」。
- **Team 時間軸只說人話**（第 5 項）：`note` 事件改用一張人話表（`noteText`），純粹重複旁邊
  那則訊息的 `reply_ok` 直接不顯示；不認得的 action（幾乎都是失敗）仍保留 `action：欄位` 原樣，
  因為那些欄位就是要拿去查的線索。`phase` 事件的代號翻成中文（`收尾中 → 已完成`），左邊那顆
  小標也從 `note` 改成 `系統`。daemon 附在每則轉送尾巴的協定提醒折成一顆 `協定提醒` chip
  （沿用既有的 `.am-chip`）；只剩提醒的那種轉送不再畫空氣泡。
- **側欄的 agent 標題只在選取列展開一行**（第 6 項）：原本跟名字擠第一行，兩邊各剩六個字。
  試過搬到第二行，結果換成把模型徽章擠成 `op…`——第二行本來就被 kind / 身份 / 模型佔滿。
  最後選「更少」：未選取的列名字獨佔第一行、標題掛在燈號 tooltip；選取中的那一列才多一行
  faint 斜體的標題（一次只有一列，清單的掃讀節奏不變，UI-DECISIONS 的 52px 也只有一列破例）。
- **選取列的弱化文字補到 4.5:1**（第 10 項）：`.bot-row.selected` 裡把 `--text-faint` 重新指到
  `--text-dim`（深色 4.49 → 5.22；選取＋hover 的混色也還有 4.58）。整列的弱化文字一起受益，
  不是只補那一個 class。
- **模型徽章的強度改用 `·`**（第 7 項）：`opus-高` / `grok-4.6-中` 的連字號讀起來像模型 id 的
  一部分（`grok-4.6-中` 看起來像 grok 的某個版本）。改成 `opus · 高`，`·` 前留 2px、顏色再退
  一階，維持一顆 chip（多開一顆 chip 會讓側欄那一行多一個元素，違反「更少」）。
  `ModelTag`、`.bot-head` 的模型列與 team 成員 tooltip 三處一起改。
- **終端分頁的工具列說「怎麼用」而不是「怎麼做的」**（第 8 項）：提示改成「唯讀快照，按
  「刷新」更新」；順手把 `source=recent_unwrapped・revision N` 收進 pane 那顆的 tooltip
  ——抓法只有在對帳時才有意義，條上留「哪個 pane、幾欄幾列、有沒有截斷」就夠了。
- **小字統一到 11px**（第 9 項）：46 條 `font-size` 從 10 / 10.5px 提到 11px（徽章、meta、chip）。
  留在 11px 以下的只剩三個，都不是「文字」：`.quota-window-name`（`5h`/`7d`，mono 細節數字）、
  `.quota-bar-pct`、`.team-queue-seq` 三個 10.5px，以及兩顆展開箭頭字元（原本 8–9px，順手提到
  10px）。實測從 89 個小於 11px 的可見文字元素降到 0。
  連帶處理放大後擠出來的兩個問題：側欄的模型徽章（`grok-4.6 · 中`）差 2px 被截，把它的左右
  padding 收成 4px；手機標題列的 kind 徽章與 `+4` 讓位，設定齒輪才不會被 `.main-title` 切掉。
- **即時氣泡的過濾補上第二批樣式**（第 1 項的續）：實機又抓到兩種——CLI 的工具活動行
  （`Moving … · 4s "user-data-dir" foo.mjs | cut -c1-120; git rm …（5s · 2 lines）`）與收尾計時行
  （`Cogitated for 5m 53s · done 2:53 AM`），還有黏在句尾的 ` · summarized`。活動行要「耗時標記
  ＋shell 的管線／分號／旗標」兩個條件同時成立才丟，免得吃掉剛好帶秒數的正常句子
  （`I waited for 3 seconds and it worked.` 會留著）。
- **第 11 項（1024px）**由第 2 輪那條 `.main-status.pane-toggle` 特異性修正一併解決：pane chip
  讓位後標題列在 1024 有大片餘裕。標題列第二行只剩一顆 `fable`（`· 低` 在 ≤1160 讓位），
  留著不動——把它搬回來只是為了填空隙。
- **PM 總結預設夾兩行**（第 12 項）：`.team-summary-text` 用 `-webkit-line-clamp: 2`，旁邊一顆
  「展開／收合」；展開後 `max-height: 34vh` 並自己捲——攤開是為了讀，不是為了佔滿畫面。
- **正常回覆不再標來源**（第 13 項）：`hook` 的 `回覆` 徽章拿掉；`terminal_fallback`（終端擷取）、
  `transcript`、`system` 仍然標——那幾種會影響你要不要信這段文字。tooltip 保留完整來源。
- **側欄操作鍵改成疊在列上**（第 14 項）：`.bot-actions` 從 `opacity: 0` 但仍佔位，改成
  `position: absolute` + 漸層底 + `pointer-events` 切換，`.bot-main` 因此從 156px 拿回 227px。
  例外：選取中的那一列操作鍵是常駐的，所以只有那一列固定讓出 64px（固定值，不會因 hover
  跳動）；`(hover: none)` 的裝置回到原本佔位的排法，免得永遠蓋住徽章。
  順帶把上一輪為了擠出 2px 而收窄的模型徽章 padding 還原。
- **手機的「↓ 最新」縮成圓鈕**（第 15 項）：蓋住的面積從約 130px 變成 34px，最後一則訊息
  讀得完整。
- **對話時間只到分**（第 16 項）：`timeOf` 帶 `hour: '2-digit', minute: '2-digit'`，完整時間仍在
  `title`。Team 時間軸沿用到秒——那是事件記錄，同一分鐘內的先後有意義。
- **Team 時間軸的時間跟氣泡對齊到分**（第 17 項）：上一輪只改了氣泡，結果同一欄出現兩種
  精度。先後順序由排列本身表達，精確到秒的時間進 `title`。
- **note 裡的成員名改用短名**（第 18 項）：`teamShortName` 已經是純函式，直接在 `noteText`
  用；`bot` 與 `pm_repeat` 的 `to` 兩處。
- **側欄 team 的清理／刪除改成 hover 才出現**（第 19 項）：`.team-node-actions` 沿用
  `.bot-actions` 的疊放做法；team 標題也因此多拿到 ~50px（`#40 [daemon/dat…` →
  `#40 [daemon/data] config.to…`）。順帶把 `.bot-row.selected .bot-main` 的 64px 讓位
  收窄成 `:has(.bot-actions)`——team 成員列也用 `.bot-row`，但它沒有那排按鍵。
- **三處原生 `confirm()` 換成 `ConfirmDialog`**（第 20 項）：Project / 主機 / 身分。順便把說明
  寫清楚——「目錄與檔案都不會動」「遠端 herdr 與 agent 不受影響」「已登入的帳號本身不受
  影響」，以及還有幾個 Bot 在用。
- **accent 文字另開一階（第 21 項）**：新增 `--accent-ink`（淺色 `#2a63cd`，深色就是 accent
  本身），把 40 條 `color: var(--accent)` 換過去；邊框、標記、按鈕底色仍用 `--accent`——
  非文字只要 3:1，而且 UI-DECISIONS 定的 primary `#2F6FE4` 沒有被改。
  掃描方式：headless Chrome 走訪所有可見文字元素，往上疊算真正的背景色（含 `color-mix`
  與半透明），對照 WCAG 4.5:1 / 大字 3:1。改完之後深淺兩色主題都是 0 個不合格。
